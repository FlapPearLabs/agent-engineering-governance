# H4 owner decisions — before build

Recommendations only, not an approved protocol or authorization to build or run. Sources: `experiments/v1.2/mechanization-gap/experiment-protocols.md` §0, §2, §4 and this directory's `TASKS.md`, `ARMS.md`, `PRECONDITIONS.md`, `MEASUREMENT.md`. Proposed runtime behavior and costs are **ASSUMED**; no H4 runtime has been measured.

1. **Task source and oracle rule.** A: keep the strict rule used consistently in rounds 2–3 and `experiments/v1.2/h2-lazy-disclosure/eligibility-schema-v2.md` §3.1; wait for or collect more real LOW history, potentially read-only from another owner project with authorization. Consequence: r27 and p01 plus false-green control t01 total 3 < 4, so `PROTOCOL_NOT_STARTABLE` remains. B: count an unrunnable/ImportError base as FAIL for an ADDED test only, if justified on principle independent of the count; p02 and p03 then qualify and the task gate is MET. This admits feature-add tasks whose base lacks the new module/API, not just repairs demonstrably failing a runnable assertion; H4 then measures a mixture of adding features and repairing existing behavior, with a changed oracle interpretation and comparability limits. Specify a worker-visible contract for the missing API and distinguish infrastructure errors from expected absence. C: lower the distinct task count per arm; §2.2 requires ≥4 tasks, so this is an explicit protocol change and narrows coverage, not an automatic waiver. **Recommend A**; do not invent tasks. Selecting B after seeing that it flips the gate is a post-hoc risk: preserve both analyses and their history, articulate the principle and inclusion criteria before collecting any new outcome, obtain owner approval, freeze and hash a revised preregistration, and label existing selection exploratory; ideally validate on newly sourced independent history. Preregistration cannot erase knowledge already acquired.

2. **Arm carriers.** A: pinned deterministic extraction and independently checked source/delivery hashes, isolated homes and a common path as in `ARMS.md`; B: manually composed prompts. A needs extraction, contamination and reachability tests; B is easier but risks treatment drift and hidden differences. **Recommend A**, with explicit A-layer sources and no fallback.

3. **Injection classes.** A: F-010 hollowed Ruff gate, caught by N7 plus exact config/real-path controls; B: expand to other E3 classes such as F-015 only after a durable-path catching gate and controls exist. A tests one class only; B improves breadth but adds unproven machinery and cost. **Recommend A first**, never claim all defect classes are covered.

4. **N per arm and power.** A: minimum ≥2 valid runs per arm and ≥4 distinct eligible tasks as a feasibility floor; B: specify paired design, effect size, non-inferiority margin, alpha, power and clustering, then calculate N and repeats. A cannot establish adequate power; B may require more tasks and resources. **Recommend B**, treating A only as a lower bound and preserving invalid cells.

5. **Budget.** A: approve a capped, separately registered exploratory phase and later a formal budget; B: fund a formal powered design directly after a defensible cost estimate. A reduces initial exposure but exploratory data cannot be mixed into formal evidence; B requires upfront sample and pricing assumptions. **Recommend A only with separate execution authorization**, pre-set per-run and total caps and recorded actual charges. Cost per run is **ASSUMED / UNKNOWN** until measured; any applicable spending approval still applies.

6. **Independent-review blinding.** A: common three-arm isomorphic schema, masked identifiers, adversarial leak tests and independent blind-review receipt; B: unblinded review with explicit limitation. A costs implementation and may still be defeated by inherently revealing content; B cannot support a blinded comparison under P4. **Recommend A**; if leakage remains, mark blinding VOID and do not treat B as P4 compliance. Exact-SHA independent review remains separate.

7. **Thresholds and stopping.** A: approve the proposed no-teeth-first precedence, high-value definition, non-inferiority margin and stops in `MEASUREMENT.md` before outcomes; B: treat the first phase as exploratory and preregister a separate confirmatory protocol. A enables a valid formal decision only if power and controls are adequate; B delays a formal conclusion. **Recommend B** if thresholds or power cannot be justified in advance; never promote exploratory findings as confirmatory.

8. **Evidence location and controls.** A: approve a durable local location outside temporary paths with access and restart verification; B: propose another storage/service with separate authorization. A requires alias and recovery tests; B adds access and dependency decisions. **Recommend A**, with pinned gate controls and no new service or source without authorization.
